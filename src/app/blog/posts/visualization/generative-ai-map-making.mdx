去年有次跟设计师吵架，起因是一张专题地图的配色方案改了七版。第七版的时候我实在绷不住了，说了一句："这颜色AI都能配得比你好。"

然后我就真的去试了。结果不是AI配得更好——而是整个过程根本不需要人了。

这篇文章是一次实验记录：用生成式 AI 做地图风格迁移和配色生成，从技术路线到实际效果，都摆出来。

## 为什么地图配色这么难

地图配色是一个被严重低估的技术活。它不是简单的"选几个好看的颜色"，而是要在几十个颜色之间建立清晰的信息层级——道路、水系、绿地、建筑、标注，每个要素的视觉权重必须跟信息重要性匹配。更麻烦的是，一套配色在浅色背景上好看，换成深色背景就完全没法看。

专业制图师调一个地图样式通常要 2-3 天。MapLibre 的 style.json 动辄几千行，每一个图层的颜色、线宽、透明度、字号都要手动调整。我见过最长的 style.json 有 16000 行——全部是手工写出来的。

生成式 AI 能解决这个问题吗？

## 实验一：Prompt → 地图样式

第一个实验：给定一段自然语言描述，让 AI 生成对应的 MapLibre 样式 JSON。

Prompt：

```
你是一个专业的地图制图师。请根据以下描述生成 MapLibre GL JS 的样式 JSON。
输出完整可用的 style.json。

地图风格描述：
- 深色主题，适合大屏展示
- 背景色接近纯黑，道路用霓虹青色
- 建筑要弱化处理，灰色半透明
- 水体用深蓝色，有微弱的发光感
- 标注用白色，字号稍大，适合远距离观看
- 整体感觉像赛博朋克风格
```

直接把这段扔给 Claude 或 GPT-4，它会输出一个完整的 style.json。我实测了几次，结论是：

- 结构完全正确，语法零错误
- 颜色选择符合"赛博朋克"的描述——深色背景配霓虹色系
- 但细节不够好：标注字号偏小（它不知道"远距离观看"意味着至少 18px 以上），水体的发光感没有实现（因为纯 style.json 做不到，需要 Shader）

跑通了，但还不够。我加了一轮迭代：

```
标注字号加大到 18-24px。
给水体加一个外发光效果——你不用管能不能实现，把相关 paint 属性设上就行。
```

第二轮生成的结果明显更接近预期。标注字号调大了，水体的 `text-halo` 属性也设置了（虽然不是真正的"发光"，但视觉效果接近）。

这个实验的核心发现是：AI 可以在几秒内生成一个结构正确、配色合理的地图样式初稿。它省掉的是"从空白到第一版"的 80% 时间。剩下的 20%——微调字号、特殊的视觉效果——仍然需要人工介入，但工作量已经大幅下降。

## 实验二：风格迁移

第二个实验更有意思——把一张照片的色彩风格迁移到地图上。

思路：上传一张照片 → AI 提取照片的配色方案（主色调、辅助色、对比色）→ 映射到地图样式的各个图层。

先让 AI 从图片里提取配色：

```
分析这张照片的色彩方案。
输出以下信息：
1. 主色调（背景大面积使用的颜色，2-3个）
2. 强调色（小面积突出的颜色，2个）
3. 中性色（用于平衡的颜色，2个）
4. 整体明暗倾向（亮调/暗调/中间调）
5. 饱和度倾向（高饱和/低饱和/自然）
```

拿一张《银翼杀手2049》的剧照做测试。AI 输出的色彩方案：

```
主色调：#1a1a2e（深蓝黑）、#16213e（海军蓝）
强调色：#e94560（霓虹红）、#0f3460（深蓝）
中性色：#533483（紫色）、#2c2c3e（深灰）
明暗倾向：暗调
饱和度倾向：高饱和点缀 + 低饱和背景
```

然后把这个配色方案映射到 MapLibre 样式上：

| 配色元素 | 地图图层 | 颜色 |
|---------|---------|------|
| 主色调-背景 | background | #1a1a2e |
| 主色调-大面积 | water, land | #16213e |
| 强调色-道路 | roads-major | #e94560 |
| 强调色-高亮 | poi-primary | #0f3460 |
| 中性色-建筑 | buildings | #2c2c3e |
| 中性色-标注 | labels | #8b8ba0（提取的紫色的淡化版） |

我用 Python 写了一个简单的映射脚本，输入 AI 提取的配色和原始 style.json，输出修改后的样式。跑完之后直接加载到 MapLibre 里，效果出奇地好——整体是银翼杀手的暗调霓虹风，建筑是深灰色半透明，高速路是霓虹红色，跟电影的美术风格高度一致。

关键是：从上传剧照到加载新样式，全程不到 2 分钟。传统地图制图师做同样的活，至少半天。

## 实验三：数据驱动的地图生成

第三个实验更进一步：直接把一份 CSV 数据丢给 AI，让它决定该怎么画。

假设有一份中国各省 GDP 数据：

| 省份 | GDP（万亿） | 增长率 |
|------|-----------|--------|
| 广东 | 13.5 | 4.8% |
| 江苏 | 12.8 | 5.2% |
| 山东 | 9.2 | 5.8% |
| ... | ... | ... |

Prompt：

```
我有一份中国各省份的 GDP 数据（见附件）。
请帮我规划一张专题地图的设计方案，包括：
1. 建议使用什么类型的地图（分级统计图/点密度图/气泡图？）
2. 如果做分级统计图，建议分几级？每级的断点和颜色？
3. 标注策略是什么？
4. 是否需要图例？图例应该放在哪里？
```

AI 的回复摘录：

```
建议使用分级统计图（Choropleth），因为数据是面状分布且适合按行政区分级展示。

分级建议：Natural Breaks（Jenks）分 5 级
- 第1级（<4万亿）：#f7fbff
- 第2级（4-6万亿）：#deebf7
- 第3级（6-8万亿）：#9ecae1
- 第4级（8-10万亿）：#4292c6
- 第5级（>10万亿）：#08519c

配色原理：单色渐变（Blues），从浅到深，
符合"数值越大颜色越深"的直觉。

标注策略：GDP > 10万亿的省份标注省份名+数值，
其余省份不标注，避免信息过载。

图例放在右下角，横向排列，标注每级范围。
```

连断点方案和具体色值都给了出来。这个回复可以直接发给前端开发，对着写代码就行。

## 实际落地的限制

三个实验做完，结论是：生成式 AI 在地图制图上确实有用，能节省大量设计时间。但不是万能的。

**限制一：无法真正"看到"效果**

AI 生成的是一个 JSON 配置，它自己不知道这个配置渲染出来是什么样子。它选的颜色是基于训练数据中的配色规律推断的，不是基于"这个颜色放在地图上好不好看"的判断。所以 AI 的输出需要加载到实际地图上验证——这个过程无法自动化。

**限制二：复杂符号化做不到**

地图符号化（symbolization）是一个专业领域——不同类型的道路画多宽、虚线还是实线、匝道怎么表示、不同缩放级别的符号切换。AI 只能做"初级制图师"的工作——给定配色和风格描述，生成大致合理的样式。精细的符号规则仍然需要人来定义。

**限制三：中国地图规范问题**

中国地图有严格的审查规范：九段线、藏南、阿克赛钦、台湾标注——这些必须在样式文件中正确体现。AI 生成的样式没有这个意识，如果不做检查直接发布，会有合规风险。

## 实际可用的工具链

基于以上实验，我目前实际在用的一套流程：

1. 用 Claude 或 GPT-4 生成初版 style.json（约 80% 完成度）
2. 用 Maputnik（开源的 MapLibre 样式编辑器）做可视化微调
3. 用 Python 脚本做批量图层替换（比如把所有道路颜色从 A 换到 B）
4. 最后手动检查中国地图的合规要素

AI 在这个流程里扮演的是"加速器"角色——把配色探索和初始生成的时间从几小时压缩到几分钟。它没有替代制图师，但让制图师的工作重心从"写 JSON"变成了"做决策"。
